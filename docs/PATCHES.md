# Changes applied to the IRIS checkout

IRIS core (`iris/src/**`, `iris/scripts/**`) is **not modified**. Our harness integrates through import and
instance-attribute injection only (see `docs/RECON.md` §8). The only files touched in `iris/` are a per-machine
configuration file that IRIS's own README tells users to edit (0001) and two benchmark metadata CSVs whose slug
spellings are inconsistent upstream (0002). Each change is kept as a patch in `patches/`
so a fresh clone can be reproduced with `git -C iris apply ../patches/<file>`.

| Patch | File | Why | Effect on results |
|---|---|---|---|
| `0001-dep-configs-local-toolchain-paths.patch` | `iris/dep_configs.json` | No sudo in WSL, so JDK 8 (Temurin 8u514-b01) and Maven 3.5.0 are installed user-space under `~/opt/` instead of `/usr/lib/jvm` and `/opt/maven` (README "Step 2: Configure Java build tools"). | None. Only used by the **native** build route (`scripts/build_one.py`, `scripts/build_codeql_dbs.py` without `--use-container`). The container route ignores it. |
| `0002-normalise-2025-slugs.patch` | `iris/data/project_info.csv`, `iris/data/build_info.csv` (5 rows each) | GATE 1 Q1 ("keep the annotated CVEs"). The 2025 additions are spelled three ways (RECON §9): `jena__CVE-…` (project_info), `jena_CVE-…` (build_info, Docker Hub), `apache__jena_CVE-…` (fix_info). Only the `fix_info.csv` spelling (`owner__repo_CVE_tag`) works with IRIS's own parsing (`iris.py:148`, `:731-732`) **and** with its fix-location scoring (`iris.py:159`). The patch renames the slug column of jena CVE-2025-49656, DSpace CVE-2025-53622, conductor CVE-2025-26074, solon CVE-2025-46096 and djl CVE-2025-0851 to that spelling. | IRIS **code** stays unmodified (the plan's GATE 1 option (a) proposed a one-line code hook; normalising the data turned out to be sufficient and smaller). The Docker images keep their Hub tag; `cueinv/build_dbs.py` pulls `…-v2:<hub tag>` and `docker tag`s it to the canonical slug before calling `scripts/build_codeql_dbs.py`. s3proxy CVE-2025-24961 is left alone (no buggy commit → excluded). Our selection reads the committed (unpatched) files via `git show`, so it is unaffected. |

Not patches, but local, untracked additions inside `iris/` (all git-ignored by IRIS or simply untracked):
* `iris/data/package-names/<slug>.txt` for projects that lacked one (conductor, djl, solon in the subset) — generated by
  `cueinv/build_dbs.py` with IRIS's own `scripts/get_packages_codeql.py` helpers (groupId from `pom.xml`/`build.gradle` + the
  `packages.ql` query on the container DB). Copies are versioned in `data/package-names-generated/`.
  If the groupId prefixes no package in the DB, the most common 3-segment package prefix is used instead when it covers
  ≥ 50 % of the DB's packages (`build_dbs.dominant_prefix`; IRIS's script offers `--internal-package` for this case).
  Only conductor needs it so far (groupId `org.conductoross`, code in `com.netflix.conductor`). See `docs/DEVIATIONS.md` D-1.
  If no groupId is found at all, it is also searched for in Gradle `buildSrc` scripts (djl; `DEVIATIONS.md` D-2).
* `iris/codeql/` — CodeQL bundle v2.23.2 (README "Step 3: Configure CodeQL"; `src/config.py:7` expects it there).
* `iris/data/project-sources/`, `iris/data/codeql-dbs/`, `iris/data/build-info/`, `iris/output/`, `iris/log/` — created by IRIS's scripts at run time.
